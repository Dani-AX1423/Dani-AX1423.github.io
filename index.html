    About
    Daniel Raj V.

    Why Systems & Programming Languages First?

    My interest in systems programming wasn't triggered by a university assignment — it grew out of frustration with taking execution environments for granted. When building applications, I kept asking what happened between writing a line of code and the CPU executing instructions. This led me straight into lexers, abstract syntax trees, and register allocation.

    Building LyTrix from scratch taught me that language design is balancing precision and developer ergonomics. Starting with a tree-walk interpreter (LyTrix-R) gave me an intuitive grasp of scope resolution and AST traversal. Moving to a QBE IR compiler backend (LyTrix-Q) forced me to think in static single-assignment (SSA) form and assembly generation.

    Arch Linux + Hyprland: Beyond "Uses Arch BTW"

    For me, operating a Linux distribution is about controlling the development surface. Moving from Fedora Silverblue to Arch Linux with Hyprland allowed me to construct a tiling environment mapped to how I process code — minimal latency, keyboard-driven navigation, and zero background clutter.

    Managing system dotfiles, writing custom Bash scripts for workspace automation, and understanding Linux process lifecycles directly informs how I structure software architectures.

    Competitive Wins: Try.Code & TECHNOVA 2026

    Under timed competition pressure at Try.Code (ISTE), I placed 1st by focusing on algorithmic clarity and clean memory execution under rapid constraint changes.

    At TECHNOVA 2026 Code Relay, competing as Team WHITE HATTERS alongside Bryan Roger B and Yugin Santhosh K, we took 1st Place by coordinating rapid modular code handoffs, debugging logic gates under strict time relays, and submitting high-precision solutions.

    Architecture Decisions & Technical Trade-Offs

    Tree-Walk Interpreter vs. Bytecode Virtual Machine

    I chose a tree-walk interpreter first for LyTrix-R to establish direct, unambiguous mapping between the parser's AST and execution state. While tree-walk interpreters suffer performance penalties from pointer-chasing tree traversal, it allowed rapid prototyping of language semantics before introducing bytecode compilation passes.

    QBE IR over LLVM for Compiler Backend (LyTrix-Q)

    When scaling to a compiled pipeline, I selected QBE (Quick Backend Engine) over LLVM. LLVM is immense and hides backend complexity behind million-line abstractions. QBE provides a clean 70% solution in 10,000 lines of C, allowing me to explicitly construct Single Static Assignment (SSA) form and understand register allocation directly.

    5. FUTURE MILESTONES & ROADMAP

    Self-hosting the LyTrix parser in LyTrix itself, expanding the standard library, and targeting bare-metal kernel entry points for eventual OS development experiments on Arch Linux.

    Engineering Breakdown & Founder Insights

    Phase 1 (FastAPI) to Phase 2 (Node/Express) Refactor

    Initial prototyping used FastAPI for quick Python integration with ML scripts. As concurrency requirements grew for multi-gate parking structures, I advocated for migrating API endpoints to Node.js/Express to leverage non-blocking I/O event loops for handling hundreds of concurrent gate camera telemetry pulses while keeping Python restricted to edge hardware.

    2-Bit Binary Adder
    Hardware Engine.

    1. THESIS STATEMENT

    Software instructions eventually boil down to voltage signals across physical logic gates. Building a physical 2-bit binary adder using 74LS series IC chips bridges theoretical boolean algebra with hardware reality.

    2. LIVE INTERACTIVE ADDER SANDBOX

    Toggle bit inputs A0, A1, B0, and B1 to simulate digital gate operations in real-time. Watch XOR, AND, and OR carry propagation update the binary output vector.
